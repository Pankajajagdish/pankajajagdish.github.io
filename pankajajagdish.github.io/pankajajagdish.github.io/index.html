Case studies

Each one follows the same path: what was wrong, how it looked before, how it looks now, and the result. Taken from production work on a telecom platform (4 AKS clusters, 8 environments).

01

Self-healing Kubernetes pods

Problem: Pods kept hitting CrashLoopBackOff and OOMKilled. Someone had to notice, log in and restart them, often outside working hours.

Before

Engineers found failures by hand. Recovery took about 2 hours and paged the on-call person.

After

A Python monitor detects failed pods, recovers them, and sends a daily health report.

2h → 5mRecovery time, with fewer on-call escalations.

  • Azure Monitor

After

Environments as code with Terraform

Problem: Environments were built by hand, so no two matched and setup was slow and error-prone.

Before

After

05

Kafka consumer lag fix

Problem: Consumers fell behind and messages piled up, delaying processing downstream.

Before

Growing lag across consumer groups, with slow message processing.

After

Tuned partitions and settings (max.poll.records, fetch.min.bytes, linger.ms, batch.size, compression).

FasterMessage processing, with the backlog cleared.
  • Apache Kafka
  • Performance tuning
  • Troubleshooting

Before

After

A Git release diff analyzer and an AKS node compliance tool run the checks automatically.

LAB DLab project

DevSecOps pipeline with no stored secrets

Code → secret scan → image scan → Key Vault → workload identity → deploy

Problem: Passwords sat in pipeline variables and vulnerable images reached production unnoticed.

Before

Long-lived credentials in pipelines, and security checks done after release, if at all.

After

Secrets live in Azure Key Vault, pods use workload identity, and the pipeline fails on leaked secrets or high-severity CVEs. RBAC limits who can deploy.

Security in the pipelineRisky builds stop before they ship.
